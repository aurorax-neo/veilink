## Rust 全异步重构实机性能实测（2026-11 Linux x86_64 实机环境）

### 测试环境
- **测试宿主**：Linux 7.0.0-38-generic x86_64 (Ubuntu)
- **运行时环境**：Rust 异步运行时 (Tokio + Hyper + Rustls)
- **拓扑形态**：Master (HTTP控制面+WebUI 28080) + Server (28443 / 28088) + Client (反向隧道) + Target (28001 Echo/HTTP) 实机进程
- **测量工具**：`iperf3 3.20`、Python 3 `time.perf_counter` 高精 RTT 往返采样器（1000 轮）、`curl` 并发基准

### 延迟瓶颈定位与根治（Nagle 算法与延迟确认）
- **问题现象**：初版在实机回环基准测试中，往返时延（RTT）稳定在 ~82.2ms（min 81.37ms / p50 82.01ms），存在非预期延迟。
- **根因推导**：
  1. 数据面套接字（Server 隧道接入、Client 连接、Mapping 入口、Target 出口）未显式配置 `TCP_NODELAY`，启用了 Nagle 算法。
  2. `write_frame` 发送逻辑将 7 字节帧头与有效载荷拆分为两次独立的 `write_all` 系统调用。首个 7 字节分节发出后，由于未填满 MSS 且存在在途未确认数据，Nagle 算法强制等待对端 ACK；对端操作系统启用延迟确认（Delayed ACK，Linux 默认 40ms），两端往返累积产生 `40ms + 40ms ≈ 80ms` 的阶跃时延。
- **优化方案**：
  1. 对全部数据面套接字接入与连接处无条件显式设置 `set_nodelay(true)`。
  2. 优化 `write_frame`，单次调用内完成 7 字节帧头与 payload 的紧凑缓冲区拼接（`Vec::with_capacity(7 + len)`），保证单帧单次网络分发。
- **优化效果**：
  - RTT 由 **82.205ms** 骤降至 **0.264ms**（p50: **0.256ms**），性能提升 **超 300 倍**。
  - 对比本地直连 TCP 回环基准（avg 0.072ms），整个反向隧道代理层引入的处理开销仅 **0.19ms**。
