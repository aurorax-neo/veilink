# 架构与边界

```text
浏览器 ─ HTTPS/本机 HTTP ─ master (SQLite)
                           ↑         ↑
                      TLS gRPC 控制面
                           │         │
公网访问 ─ 映射 TCP 端口 ─ server ← client ─ 内网 TCP 服务
                         入口      出口
                           └─ VLESS/TCP+TLS ─┘
```

## 三个角色

- **master**：管理员鉴权、节点登记、绑定与映射持久化、配置版本分发和状态汇总；不承担隧道业务流量。
- **server**：公网 VLESS/TLS 入口和固定目标 TCP 监听器。只接受已登记身份访问对应反向域名、且端口为 0 的控制连接。
- **client**：从内网主动连出，接收入口复用过来的请求，并只拨号该绑定下已启用映射的精确目标。

同一 Go 程序通过不同子命令运行；公网机器可同时部署 master 和 server，但两者仍是独立进程及信任边界。

## 绑定与隔离

一个 binding 将 server 与 client 关联，具有独立 UUID、reverse 标记域名和路由标签。reverse 域名是协议内部标记，不要求 DNS 解析或为其签发证书。TLS ServerName 是网关真实证书中的身份，二者不要混用。

网关只把**对应 VLESS 身份**连到**对应反向域名**且端口为 0 的控制流交给该 binding。公网映射监听器固定从这条反向连接上开流。客户端拒绝任何未授权的 host:port，不提供通用代理。

## 同步语义

控制面使用 TLS gRPC。节点注册令牌是有时限、一次性凭据；注册后使用独立节点凭据建立事件流并拉取授权快照。完整快照含版本号，节点串行应用并回报实际成功版本。事件通知仅提示需要同步，不证明配置已经生效。

- **desired revision**：管理中心期望节点运行的版本。
- **applied revision**：节点确认成功运行的版本。
- **last seen**：控制面最近心跳，仅表示节点通信状态。
- **error**：配置获取或应用失败信息。

server/client 两端属于最终一致性系统，不是分布式原子更新。只有相关双方均成功应用时，映射配置才算已下发；即使如此，仍不能从心跳推断后端目标服务健康。

## 生命周期

`internal/tunnel` 预校验快照后串行切换运行实例。配置变更会先停掉当前监听和反向连接，再按新快照启动，因此该节点已有连接会短暂中断，不保证无损热更新。启动失败时尝试恢复上一份成功配置；恢复失败必须保留故障状态，不能虚报已应用。

节点保存最后成功快照和自己的凭据，文件需保持私有。master 失联不会主动拆掉正在运行的数据面；恢复后重新同步。节点离线期间无法即时感知凭据吊销。撤销权限需相关在线网关收到新配置；紧急情况下还应通过防火墙或停止网关立即阻断。

## 首版范围

支持 TCP 端口映射，可透明转发 HTTP、TLS 和 SSH 等 TCP 应用。不会终止目标应用的 TLS。仅内网客户端到公网网关的 VLESS 链路由本工具自动使用 TLS 保护；公网访问者到映射端口之间是否加密取决于应用协议本身。

不提供 UDP 映射、域名虚拟主机路由、P2P 打洞、自动签发证书、REALITY、远程终端或多租户计费。
