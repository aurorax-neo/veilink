# 架构与边界

Veilink 是一款专注于安全、高性能内网穿透的轻量化系统，采用原生 Go 实现的 VLESS + 私有多路复用（Mux）+ XUDP 隧道协议。架构上清晰解耦**控制面**与**数据面**，并同时支持**分布式部署**与**单机一体化（All-in-One）部署**。

---

## 1. 部署架构模式

### 模式 A：分布式多节点部署 (Distributed Mode)

适用于大型网络、拥有多台公网边界网关服务器（不同地理区域或运营商网络）、或者需要将管理中心与公网入口在物理机/容器上严格隔离的生产场景。

```text
                               ┌────────────────────────────────┐
                               │       master (控制面)          │
                               │  HTTPS :8443 (Web + REST API)  │
                               │  TLS gRPC :8443 (配置与事件流)   │
                               └───────▲────────────────▲───────┘
                                       │                │
                        gRPC 控制通道  │                │ gRPC 控制通道
                     (配置拉取/状态上报)│                │ (配置拉取/状态上报)
                                       │                │
           ┌───────────────────────────┴────┐      ┌────┴───────────────────────────┐
           │     server-1 (公网网关A)        │      │     client-1 (内网客户端)       │
           │  VLESS/TLS 监听器 :4433         │◄─────┤  主动向 server-1 建立反向隧道   │
公网用户 ─►│  映射公网端口 :8080 (TCP/UDP)   │ (反向)│  连接局域网目标 (e.g. :80/:22)  │
           └────────────────────────────────┘      └────────────────────────────────┘
```

- **Master 职责**：管理员鉴权、SQLite 数据库持久化、生成节点一次性注册令牌、维护 desired 配置快照、下发 gRPC 事件流。自身**不经手任何隧道业务数据流量**。
- **Server 职责**：独立运行在公网节点，监听 VLESS 反向控制隧道端口，并在收到配置后拉起公网 TCP/UDP 映射监听端口。
- **Client 职责**：部署于内网私网环境，主动向 Server 发起出站 TLS 连接。

### 模式 B：单机一体化网关部署 (All-in-One Embedded Mode)

适用于个人自建、单台公网 VPS、或轻量化边缘节点场景（类似 frp-panel / frps 整合部署）。通过在 `master` 中配置 `embedded_server.enabled: true`，直接在 Master 进程内拉起数据面 Server 网关。

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        master (单机一体化进程)                          │
│                                                                        │
│  ┌──────────────────────────────┐    ┌──────────────────────────────┐  │
│  │       控制面 (Control)       │    │   内置网关 (Embedded Server) │  │
│  │  HTTPS :8443 (Web + API)     │    │  VLESS/TLS :8444 数据面通道  │  │
│  │  TLS gRPC :8443 (内置通道)   │◄───┤  映射公网端口 :8080 (TCP/UDP)│  │
│  └──────────────────────────────┘    └──────────────▲───────────────┘  │
└─────────────────────────────────────────────────────┼──────────────────┘
                                                      │ VLESS 反向隧道
                                                      │ (客户端主动出站)
                                       ┌──────────────┴──────────────────┐
                                       │     client (内网穿透客户端)      │
                                       │  连接局域网目标 (e.g. :80/:22)  │
                                       └─────────────────────────────────┘
```

- **免令牌零干预引导**：Master 启动时检测到 `embedded_server.enabled: true`，自动在数据库中查验/创建该内置网关的节点记录，为其签发专用长期注册凭证，并在内部直接启动 `server.Run` 网关协程。
- **混合组网兼容**：一体化 Master 运行内置网关的同时，**仍完全支持**外部独立的分布式 `server` 节点连入与注册，两者无缝并存。
- **优雅停机**：Master 接收 SIGINT/SIGTERM 信号时，先停止接收外部请求并优雅取消内置网关生命周期上下文，内置网关平滑释放所有数据面监听端口与活动连接，最后优雅关闭 gRPC 与 HTTP 控制面。

### 两种模式特性对比

| 维度 | 分布式多节点模式 (Distributed) | 单机一体化模式 (All-in-One Embedded) |
| :--- | :--- | :--- |
| **适用场景** | 多公网网关、跨机房集群、控制与数据严格隔离 | 单台公网服务器、快速验证、个人 NAS/内网设备穿透 |
| **进程数量** | 2+ 进程（Master 独立，每个 Server 独立） | 1 个公网进程（Master + 内置 Server） |
| **网关令牌配置** | 需要通过控制台手动生成令牌并注入环境变量 | 零手动配置，Master 自动初始化并登记节点 |
| **数据面端口** | 独立于 Server 机器的监听端口 | 在 Master 机器上开放 VLESS 端口与映射端口 |
| **可用性隔离** | 某个 Server 故障不影响 Master 控制台和其他 Server | 单进程重启同时重载控制面与内置网关（已运行 Client 自动重连） |

## 2. 角色与信任边界

1. **Master（控制面）**：
   - 监听 `bind_addr`（默认 `0.0.0.0:8443`），在单个 TLS 端口上通过 ALPN 与 HTTP 路由多路复用提供：
     - `/` 及静态资源：Vue 3 编写的前端管理控制台。
     - `/api/*`：管理 RESTful API，采用 CSRF Token 与 `SameSite=Strict` Cookie 认证。
     - `/healthz` 与 `/api/health`：用于容器与反代探活的健康检查端点。
     - `gRPC` 服务：供所有 Server 与 Client 节点建立长连接，接收配置变更事件。
   - 数据存储于 SQLite，绑定密钥通过部署密钥（`veilink.key`）经 AES-256-GCM 加密保存，API 从不泄露底层 VLESS UUID。

2. **Server（数据面公网网关）**：
   - 监听公网数据面端口（默认 `4433` 或一体化模式的 `8444`），使用原生 VLESS 协议。
   - 仅接受持有受信任节点凭据的 Client 发起的反向隧道建立请求。
   - 严格根据 Master 下发的映射规则绑定监听本地端口，不提供开放代理转发。

3. **Client（数据面内网出口）**：
   - 主动向公网 Server 建立出站 TLS/REALITY 连接，**无需公网 IP，不开放任何公网监听端口**。
   - 接收 Server 多路复用分发的连接请求后，严格只拨号当前绑定规则中明确授权的目标内网 `host:port`。

## 3. 隧道传输与协议特性

### TCP 映射与私有 Mux
- TCP 流量采用原生高效的单连接多路复用（Private Mux）协议。
- 支持单条反向连接复用多个公网请求，显著降低连接握手延迟；Client 可通过 `pool: 4` 配置连接池并发度。
- 全透明转发，不解密终端应用 TLS，保持端到端完整安全性。

### UDP 映射与 XUDP 封装
- UDP 映射采用标准 XUDP 数据报帧封装协议，将无连接的 UDP 数据报嵌入到既有的 VLESS Mux 流中进行传输。
- 网关端为每个公网对端维护独立的 8 字节全局 Session ID 与连接表（具备 2 分钟闲置超时清理与并发安全保护）。
- 客户端在内网建立局部 Connected UDP Socket 转发报文并将回包路由回原公网对端，杜绝任意 UDP 放大攻击与开放反弹。

### 传输层安全选项（三选一）
1. **标准 TLS（默认推荐）**：Server 配置公网证书与私钥，Client 配置 CA 校验证书链。
2. **REALITY（伪装去特征）**：无需公网证书，Server 对外呈现目标合规站点（如知名 CDN）的 TLS 握手特征，未授权探测流量回落至 `dest`，彻底消除特征识别。
3. **Hysteria2（QUIC 传输）**：基于 UDP/QUIC 传输外层报文，具备极强的弱网抗丢包与高延迟网络穿透表现。

## 4. 生产级运维与反向代理

在生产环境中，通常推荐将 Master 控制台与网关置于专业反向代理（如 Nginx）之后：
- 通过 Nginx 提供规范的生产 TLS 证书管理（如 Let's Encrypt / ACME 自动续签）。
- 单一公网 443 端口通过 Nginx `stream` 模块的 SNI Preread 分流，或 HTTP/2 `grpc_pass` 桥接，实现 Web 控制台、gRPC 与数据面的优雅共存。
- 详细的反向代理拓扑与现成配置范例，请参阅：[docs/nginx-reverse-proxy.md](nginx-reverse-proxy.md)。
